### What it does
1. **Deploy**: Deploys `DataSubjectRights` to preprod/preview/standalone
2. **Join**: Joins existing deployment at a known address (`--join <address>`)
3. **Demo**: Runs full LGPD Art. 18 rights request lifecycle

### Demo scenario
- Subject "Carlos Mendez" (identified only by `sha256("carlos.mendez@example.com.br")`)
- Controller "Acme Fintech LTDA" (identified only by `sha256("00.000.000/0001-00")`)
- No PII on-chain — only hashes

Demo steps:
1. `submitRequest` — type 1 (Art. 18 I: confirmation — is my data being processed?)
2. `getRequestStatus` → 1 (open)
3. `fulfillRequest` at +100 blocks (well within 21600-block / 15-day Art. 19 deadline)
4. `getRequestStatus` → 2 (fulfilled)
5. `submitRequest` — type 2 (Art. 18 II: data access — provide a copy of my data)
6. `rejectRequest` (Art. 18 §4 rejection — justification stored off-chain in case management)
7. `getRequestStatus` → 3 (rejected)
8. Query counters: `getTotalRequests`, `getTotalFulfilled`, `getTotalRejected`, `getTotalOverdue`
9. `getRequestType` + `getRequestSubmittedBlock` (auditor verification pattern)

### Key helper: `computeRequestId()`
```typescript
function computeRequestId(subjectId, controllerId, reqType, nonce): Buffer {
  return createHash('sha256')
    .update(subjectId).update(controllerId)
    .update(Buffer.from([reqType])).update(Buffer.from([nonce]))
    .digest();
}
```
Matches the `request_id = keccak256(subject_id || controller_id || req_type || nonce)` design
documented in the DataSubjectRights.compact header. (Using sha256 here for Node.js compatibility;
for production use keccak256 to match Compact/EVM ecosystem conventions.)

### markRequestOverdue() — not in demo
The `markRequestOverdue()` circuit requires `current_block >= submitted_block + 21600`.
In a live network this means waiting 15 days; in standalone, set `submitted_block=1` and pass
`current_block >= 21601`. Documented in the demo output message.
