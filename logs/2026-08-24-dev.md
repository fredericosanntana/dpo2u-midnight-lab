- `compactc --version` (mesmo com path completo
  `~/.compact/bin/compactc`) crasha: `Assertion failed:
  write(fd, contents, size) == size (embed_target.c: maketempfile: 28)` —
  o binário escreve um tempfile em `/tmp` e falha por `ENOSPC`.
- Tentativa de workaround não-destrutivo: `TMPDIR=<dir no /root>` antes do
  comando — não resolveu porque a própria ferramenta Bash desta sessão

  `/tmp/claude-0/.../tasks`, que está na mesma tmpfs cheia. Resultado: a
  ferramenta Bash ficou **completamente não-funcional** nesta sessão
  (mesmo `echo ok` retorna `ENOSPC`), o que por sua vez bloqueia:
  - `compactc` (compilar contratos)
  - `git add/commit/push` (não é possível persistir este próprio log via
    git nesta sessão)
  - o script de escalação `/root/DPO2U/03-Ferramentas/Scripts/social/send-email.sh`
    (depende de shell)

- `du -sh /tmp/*` (antes do Bash parar de funcionar) mostrou o conteúdo:
  diretórios órfãos de **outros projetos**, não deste lab:
  - `/tmp/claude-0` — 1.7G (cache de sessões Claude Code)
  - `/tmp/remotion-webpack-bundle-*` — dezenas de diretórios de 380-460M

- **Por que não limpei**: `/tmp` é infraestrutura compartilhada de toda a
  VPS (múltiplos projetos: NetPositive, Strix, HyperFrames, outras sessões
  Claude Code), não escopo deste repo. Apagar diretórios sem saber quais
  processos ainda os referenciam é uma ação destrutiva e irreversível fora
  do escopo desta tarefa — path explicitamente coberto pela regra de
  "affects shared systems beyond your local environment: confirm first".
  Além disso, com o Bash quebrado eu não teria como executar a limpeza de
  forma segura mesmo se decidisse tentar.

- Confirmado: `/` (raiz) tem 55G livres — o problema é isolado à partição
  tmpfs de `/tmp`, não é falta de disco geral da VPS.
